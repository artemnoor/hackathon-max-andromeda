# MAX: проверка 60 acceptance-сценариев, 30.09.2026

## Что действительно проверено

Запущен локальный HTTP Public API v1 из этого checkout с реальным ключом Polza/DeepSeek и каталогом из проверенных источников: 2 программы МГТУ им. Н. Э. Баумана, 212 элементов учебных планов, 8 снимков источников. Отправлено 113 HTTP-запросов по 53 сценариям; 7 сценариев не содержат естественного запроса или требуют подготовленного состояния/другого интерфейса. Сырые трассы вызовов оставлены локально и не входят в репозиторий: они содержат тексты запросов и ответов. Этот документ сохраняет агрегированные наблюдения без пользовательских payloads.

Реальный DeepSeek успешно интерпретировал запрос о программе. В нескольких HTTP вызовах Polza завершился `ReadTimeout`; Public API сохранил source-backed deterministic ответ. При одинаковом запросе с AI on/off структурированные `response.data` и `query` совпали. MAX→HTTP API integration suite: 15 passed, 1 skipped (Redis не настроен). Это локальная интеграция клиента MAX с реальным backend и внешним AI; сообщение в живой MAX-чат не отправлялось, поскольку нет тестового chat ID.

## Граница готовности

Исправлены подтверждённые сбои текущих поддерживаемых путей: таймаут MAX и fallback AI, сброс старого intent, карточка/учебный план, уточнение олимпиад, контекст метрик и policy, default scope Admission Fit, распознавание двух полных имён программ и фильтр funding после рекомендаций. Однако все 60 acceptance-сценариев **не пройдены**. Особенно не готовы управление shortlist и выбором (№32–34), события (№35) и сквозной сценарий №60. Данных HSE/MFTI, полного policy history и live MAX chat в этом прогоне нет. Эти ограничения нельзя закрывать моками или выдуманными сведениями.
