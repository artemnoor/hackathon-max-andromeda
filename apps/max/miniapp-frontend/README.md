# Andromeda Admissions Mini App

This directory contains the JavaScript frontend for the MAX Mini App. Vite builds it into `dist`; the Node.js/TypeScript host serves that production build. PowerShell labels in repository documentation refer to command examples, not the frontend language. The former `apps/max/miniapp` shell is no longer served.

The old standalone `/v1` client and demo program records are outside the active build; the bundled program array is empty and catalog records come from Andromeda. The active navigation includes catalog and program details, curriculum comparison, admission check, profile, shortlist, ProfTest, recommendations, personal route, news/events, olympiads and admission rules. The Mini App host maps an explicit allowlist of requests to canonical Andromeda Public API v1. Public catalog reads can run in browser preview; requests that use personal profile data require server-side verification of signed MAX launch data.

Data and persistence are mixed by design. Program, curriculum, admission-offering and benefit data come from the API. The admission check asks the backend for an admission-fit result. Profile inputs, EGE scores, shortlist, comparison selection and progress are stored in browser `localStorage`; EGE scores are not currently synchronized to the Andromeda profile. Recommendations use the server-side profile, while the personal route is calculated from browser-local progress. News combines API events with curated source-linked stories. The bundled olympiad data is currently empty, so that page has no olympiad records to display.

Build from `apps/max` with `npm run build:miniapp`; run the host with `npm run dev:miniapp`. Set `ANDROMEDA_API_BASE_URL` on the MAX host to the reachable backend. Expose the host through HTTPS, add its public origin to `MINI_APP_ORIGINS`, and set `MINI_APP_PUBLIC_URL` to the same origin to display the native MAX launch button. Do not put API secrets or MAX tokens into Vite environment variables. When opened from MAX, the client sends available signed launch data in `X-Max-Init-Data`; the browser does not store that proof. Public catalog calls do not require a MAX launch, while profile-based calls do.

The original `docs/api/openapi.yaml` describes the upstream standalone prototype and is not the MAX contract. The canonical client contract is `services/andromeda/openapi.json`, with generated DTOs under `apps/max/src/andromeda/generated`.
